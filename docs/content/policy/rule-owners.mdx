# Rule owners

S1 contract: native alint owns every check it can express; the
`rust-repository-policy` helper owns only the narrow gaps. Trust gate:
spawn/command rule kinds are allowed only in an adopter's own top-level
config, never via `extends`.

## Native alint owns

| Check | Native kinds (probed 2026-10-06) |
|---|---|
| Manifest inheritance, enumerated keys | `toml_path_equals` deep-equals `{workspace: true}` |
| Patch-section ban | `toml_path_absent` for `$.patch` |
| Per-file line limits | `file_max_lines` |
| Test path layout | `file_absent` + `dir_contains` + `dir_only_contains` (require/allow are direct-child basename globs, not recursive) |
| Docs location | `file_absent` with `root_only` + include/exclude, plus `dir_exists` |
| Toolchain pins + CI parity | `toml_path_equals` + cross-file `equals` (use `normalize: semver-minor` for format drift) |
| CI enumerated jobs/steps | `yaml_path_equals` / `yaml_path_absent` (dashed keys need bracket notation) |
| Renovate config | `json_path_equals` / `json_schema_passes` (JSONC-tolerant) |

Probe: alint 0.17.0, pinned ref v0.16.1 rules.md, 94 native kinds,
zero aggregate kinds.

## Module rule IDs

All 36 rules are `level: error`, use only the probed native kinds
above (no command/spawn kinds: the trust gate loads those only from an
adopter's own top-level config), and ship per-rule
`accepted`/`rejected`/`boundary` fixtures under
`fixtures/modules/<module>/<rule-id>/`. Accepted fixtures pass their
whole module; rejected fixtures fail only the target rule; boundary
fixtures pin edge semantics (documented pass/fail each).

| Module | Rule IDs | Purpose |
|---|---|---|
| `modules/layout.yml` | `layout-crates-dir`, `layout-github-dir` (`dir_exists`, one rule each: lists are OR) | Required root dirs |
| | `layout-root-files` (`file_absent`, `root_only`) | No `*.log`/`*.tmp`/`*.bak` at root (nested pass) |
| | `layout-no-backup-files`, `layout-no-merge-leftovers` (`file_absent`) | No `*~`/`*.swp`/`*.swo`, no `*.orig`/`*.rej` |
| | `layout-requires-cargo-toml`, `layout-requires-cargo-lock`, `layout-requires-mise-toml`, `layout-requires-rust-toolchain`, `layout-requires-rustfmt-toml`, `layout-requires-clippy-toml`, `layout-requires-deny-toml`, `layout-requires-nextest-config`, `layout-requires-renovate-json`, `layout-requires-alint-yml` (`file_exists`, one single-path rule each) | Required root files incl. dotfiles (a DIR at the path fails) |
| | `layout-no-flat-crate-manifest` (`file_absent` `crates/*/Cargo.toml`), `layout-no-deep-crate-manifest` (`file_absent` `crates/*/*/*/**/Cargo.toml`) | S4: members at exactly `crates/<group>/<package>` (flat and depth-3+ banned; depth-4 boundary fails) |
| `modules/cargo.yml` | `cargo-workspace-inherit-edition`, `cargo-workspace-inherit-license`, `cargo-workspace-inherit-lints` (`toml_path_equals` `{workspace: true}` over `crates/*/*/Cargo.toml`) | Enumerated inherited keys at depth 2 (absent key fails) |
| | `cargo-no-patch` (`toml_path_absent` `$.patch`, even empty) | Patch-section ban |
| | `cargo-workspace-resolver` (`toml_path_equals` `"3"`) | Resolver pin (string, not integer) |
| `modules/tests.yml` | `tests-dir-present` (`dir_contains` `crates/*/*` `tests`) | Every depth-2 crate has `tests/` (a FILE named `tests` also satisfies; flat is layout's ban) |
| | `tests-only-rust` (`dir_only_contains` `*.rs`) | Only `*.rs` under `tests/` (`.gitkeep` fails) |
| | `tests-no-test-files-in-src` (`file_absent` `*test*.rs` minus `tests.rs`/`tests/**`) | Non-suite `*test*` files live in `tests/` (`latest.rs` fails: substring; canonical `src/tests.rs` and `src/tests/<case>.rs` pass: helper-owned) |
| `modules/docs.yml` | `docs-dir-present` (`dir_exists`) | `docs/` exists |
| | `docs-root-only-allowed` (`file_absent`, `root_only`) | Root markdown allowlist: README/CHANGELOG/AGENTS/CLAUDE only |
| `modules/toolchain.yml` | `toolchain-channel-pinned` (`toml_path_equals` `"1.98.1"`) | Exact channel pin (`"1.98"` fails) |
| | `toolchain-mise-parity` (`cross_file`, `semver-minor`) | `mise.toml` rust matches channel (patch drift passes) |
| | `toolchain-ci-parity` (`cross_file`, `semver-minor`, missing tolerated) | CI pins match channel; workflows without a pin pass |
| `modules/ci.yml` | `ci-build-runs-on` (`yaml_path_equals` `ubuntu-latest`) | `build` job present and on `ubuntu-latest` (`ubuntu-24.04` fails) |
| | `ci-no-pull-request-target` (`yaml_path_absent`) | No `pull_request_target` trigger (`pull_request` passes) |
| `modules/renovate.yml` | `renovate-config-schema` (`json_schema_passes`, vendored `renovate.schema.json`) | Non-empty `extends` (`extends: []` fails; missing schema file fails) |
| | `renovate-schema-url` (`json_path_equals` `$['$schema']`) | Canonical `$schema` URL (`http:` fails) |
| `modules/size.yml` | `size-file-400` (`file_max_lines` 400, `**/*.rs` minus fixtures/testdata/target/.cache/node_modules) | 400 lines pass, 401 fail |
| | `size-lib-main-150` (`file_max_lines` 150, `src/lib.rs`/`src/main.rs` minus target/.cache/node_modules) | `src/` entry points: 150 lines pass, 151 fail (`tests/main.rs` runners exempt at any size under 400) |

Assembled by `profiles/rust-strict-v1.yml` (extends all 8 modules,
36 rules) with top-level `respect_gitignore: false`: policy linting
must not honor `.gitignore`, otherwise any content rule is one
ignore-line away from evasion (a gitignored 500-line file passed
`size-file-400` before the flag). Trade-off: the walked tree widens
to build output, so the size rules exclude `target/`, `.cache/`,
`node_modules/` explicitly; adopters with other generated trees add
their own excludes rather than re-enabling ignore-honoring.
Profile-level proof ships as `fixtures/golden-ok` (0 violations on a
fully canonical package: `src/tests.rs` + `src/tests/<case>.rs` split
plus a `tests/main.rs` integration runner) and
`fixtures/golden-bad` (exactly 5: `cargo-workspace-inherit-edition`,
`tests-dir-present`, `layout-no-flat-crate-manifest`,
`ci-build-runs-on`, and `size-file-400` via a gitignored file).
Proven-unenforceable with native kinds (fixtures omitted): multi-file
AND in ONE exists rule (lists are OR; one single-path rule per file
works, dotfiles included), dotfile BANS with `file_absent` (walker
skips dotfiles there), whole-repo aggregates (no sum kind:
helper-owned).

## Helper owns (gaps)

| Gap | Why native cannot |
|---|---|
| Open-ended all-inheritable-keys check | Needs Cargo inheritable-key knowledge |
| CI recipe-to-job set parity | JSONPath cannot extract YAML key names |
| Size aggregates | No sum kind; use command-rule plumbing |
| Rust syntax checks (test placement in production files, dependency direction, package inventory) | From contract, still to prove |

## Release install

Each `v*` tag ships one versioned artifact,
`rust-repository-policy-<ver>.tar.gz` (plus a `.sha256` sidecar),
containing `modules/`, `profiles/`, `schemas/`, and the helper binaries
under `bin/linux-x86_64/` and `bin/macos-arm64/`.

Pins (probed; newer versions not yet validated):

- alint `0.17.0` — e.g. `cargo install alint --version 0.17.0 --locked`
  (also Homebrew `asamarts/alint`, npm, PyPI; not in the Mise registry
  as of 2026-10-06).
- Mise `[tools] rust = "1.98.1"`, matching `rust-toolchain.toml`
  (`toolchain-channel-pinned` enforces the channel exactly; the parity
  rules reconcile patch drift).
- Helper `rust-repository-policy` at the release tag version, on `PATH`.

Materialize into `.cache/rust-policy/` (the size rules exclude `.cache/`):

```sh
ver=0.1.0
curl -LO "https://github.com/tailrocks/rust-repository-policy/releases/download/v$ver/rust-repository-policy-$ver.tar.gz"
curl -LO "https://github.com/tailrocks/rust-repository-policy/releases/download/v$ver/rust-repository-policy-$ver.tar.gz.sha256"
sha256sum -c "rust-repository-policy-$ver.tar.gz.sha256"
rm -rf .cache/rust-policy && mkdir -p .cache/rust-policy
tar -xzf "rust-repository-policy-$ver.tar.gz" -C .cache/rust-policy --strip-components=1
install -m755 .cache/rust-policy/bin/macos-arm64/rust-repository-policy ~/.local/bin/
```

Keep `.cache/` gitignored and re-run materialization in CI before
`alint check`. Vendor `schemas/renovate.schema.json` to
`renovate.schema.json` at the repo root (`schema_path` resolves at the
lint root), and add the three `policy/*.json` registries (see [Gap
checks](/policy/gap-checks)).

Adopter `.alint.yml` — the profile plus the one trust-gated command
rule, with the anti-evasion flag repeated top-level:

```yaml
version: 1
respect_gitignore: false
extends:
  - ./.cache/rust-policy/profiles/rust-strict-v1.yml
rules:
  - id: policy-gaps
    kind: command_idempotent
    command: ["rust-repository-policy", "check-gaps", "--root", "."]
    files_from: stdout
    files_pattern: "^\\S+ (\\S+?):\\d+:"
    level: error
```

The top-level `respect_gitignore: false` is load-bearing: the profile's
own setting does not propagate through `extends` (probed 2026-10-06 on
alint 0.17.0 — a gitignored 500-line file passed `size-file-400`
without it).

Trust boundary (all probed on alint 0.17.0): `allow_out_of_root:
true`, `baseline:`, and command/spawn rule kinds are refused in any
extends-reached config, so the profile ships none of them. The adapter
needs no `allow_out_of_root` either: every `extends` target and
`schema_path` resolves in-root under `.cache/rust-policy/`. Direct
`-c` use of the profile from a foreign lint root (e.g. the golden
fixtures) needs `allow_out_of_root: true` on the invoking top-level
config instead — the flag can never live in the profile itself.

Verify: `alint validate-config .alint.yml` reports 37 rules and `alint
check` passes. The install proof lives in `fixtures/install/` (the
`ok/` consumer repo plus the `check-install.sh` release gate: clean
pass on a fully canonical package (suite split + integration runner,
green on every native rule plus every gap), one mutation per module,
one helper-gap defect, and the exactly-one-invocation count).
